# Publish the API Reference for Free

This publishes static API documentation, not the Java backend. Visitors can read
Products, Orders, Inventory, schemas, examples, and the architecture. All backend
execution is disabled. No payment, server, custom domain, or deployment SSH
credentials are needed for GitHub Pages on a public GitHub Free repository.

## 1. Export the Current API

From Windows PowerShell in the project folder:

```powershell
cd C:\Users\islam\Desktop\microservice-new
docker compose up -d
powershell -NoProfile -File scripts/Export-ApiDocs.ps1
```

Wait until the combined local documentation loads before exporting. The script
downloads /openapi/all and the gateway's Swagger assets. It replaces local setup
instructions with a public architecture overview, removes local demo credentials
from that overview, and uses a deliberately invalid backend URL. The assets and
OpenAPI snapshot are committed so GitHub never needs to contact your computer.

The Swagger UI license download is pinned to 5.30.1, the version supplied by
Springdoc 3.0.0 in this project. Update it when upgrading Springdoc/Swagger UI.

## 2. Commit and Push the Documentation

Review these paths, then commit only the Pages work:

```powershell
git add docs-site scripts/Export-ApiDocs.ps1 .github/workflows/pages.yml docs/github-pages.md README.md
git commit -m "Add static API reference for GitHub Pages"
git push -u origin feature/microservices-documentation
```

The branch above is the current branch when these instructions were prepared.
If working on a different branch, use that branch name instead. These commands
have not been executed for you.

## 3. Merge to the Default Branch

Open https://github.com/islamsoliman1/microservice-new.

Create a pull request from feature/microservices-documentation into the
repository's default branch and merge the reviewed changes.

The Pages workflow publishes only from the default branch. It is independent
of the Java CI/CD workflow, so publishing does not require Docker builds or a
Hetzner/Oracle server. The existing Java workflow may run separately.

For GitHub Free, the repository must be public for Pages. If it is private and
you want to keep its source private, publish only docs-site and a Pages workflow
from a separate public documentation repository instead.

## 4. Enable GitHub Pages

In the repository, open Settings -> Pages. Under Build and deployment, set
Source to GitHub Actions. Use the included workflow; do not add a second template
or choose a branch folder as the publishing source.

If a deployment ran before Pages was enabled, rerun it after changing this setting.

Official steps:
https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## 5. Run the Workflow

Open Actions -> Publish API Documentation -> Run workflow.
Select the default branch and run it. Wait for the job to finish successfully.

The workflow uploads only docs-site, rather than the repository root. GitHub
provides its deployment token automatically; no paid service or PAT is needed.

Official workflow reference:
https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages

## 6. Open and Verify the Site

The expected project URL is:

https://islamsoliman1.github.io/microservice-new/

Use the URL shown in Settings -> Pages or the workflow deployment output as
the authoritative address. This URL is not live merely because files exist
locally; Pages must be enabled and the deployment must complete.

Check that all three API sections load, schemas/examples expand, and no Try it
out or credential entry controls appear. Test in a private browser window and
on your phone. The site should load even when Docker on your computer is stopped.

Use the CV label: API Documentation & Demo. Add a demo video link separately
once a real recording exists; no recording has been generated by this setup.

## Update the Reference

After changing API controllers/DTOs:

1. Rebuild and start the local services.
2. Run scripts/Export-ApiDocs.ps1 again.
3. Commit the exported docs-site changes and merge them to the default branch.

The Pages workflow then publishes the updated snapshot automatically.

## Troubleshooting

- 404: check repository visibility, Pages Source, the workflow result, and the
  exact project URL including /microservice-new/.
- Blank Swagger: ensure openapi.json and both assets were committed. All site
  asset URLs are relative so they work beneath the repository URL prefix.
- Workflow skipped: it publishes only the repository's default branch.
- Workflow not listed: merge pages.yml into the default branch first.
- 503 during export: the local gateway cannot load all three service definitions.
  Wait for Eureka registration and inspect service logs before retrying.
